# Django-проекты: веб-разработка

Репозиторий содержит независимые веб-приложения на Django. Каждое приложение запускается отдельно.

## 🛠 Общий стек технологий
*   **Язык:** Python 3.12+
*   **Фреймворк:** Django 4.x / 5.x
*   **Базы данных:** SQLite (для задач 1, 2.1, 2.2, 2.3), PostgreSQL (для задачи 2.4)
*   **Работа с файлами:** `openpyxl` (для чтения/записи Excel-файлов в приложении Z1), `Pillow` (для ImageField в приложении Z3)

---

## 📂 Структура репозитория

```text
web_Hello_var_18/
├── web_Hello_var_18/      # Приложение Z1: работа с файлами txt/xlsx
├── Z2_1/                  # Приложение Z2.1: CRUD для одной таблицы (SQLite)
├── Z2_2/                  # Приложение Z2.2: CRUD со связью 1 ко многим (SQLite)
├── Z2_3/                  # Приложение Z2.3: CRUD со связью многие ко многим (SQLite)
├── Z2_4/                  # Приложение Z2.4: CRUD со связью 1 к 1 (PostgreSQL)
├── Z3/                    # Приложение Z3: билетная касса (5 таблиц)
└── README.md              # Этот файл
```
📝 Приложение Z1: web_Hello_var_18

Тема: «Заказ билетов». Работа с маршрутизацией, шаблонами и формами без использования БД.

    Хранение данных: Текстовые файлы (.txt) и таблицы Excel (.xlsx) в папке tablica.

    Реализовано:

        Маршрутизация (path, re_path, параметры по умолчанию).

        Шаблоны (наследование от base.html, вывод списков, словарей, циклы).

        Формы (forms.py): валидация телефона и даты, выбор рейса, чекбоксы доп. услуг, сохранение заказа в Excel.

        Динамические страницы: расписание, фильтр по дням недели, информация о рейсе, список автобусов и заказов.

Инструкция по запуску находится внутри папки web_Hello_var_18 (через run.bat или вручную).
📝 Приложение Z2.1: Папка Z2_1 (Одна таблица)

Тема: Управление автобусами.

    База данных: SQLite.

    Модель: Bus (Название, количество мест).

    Реализовано: Полный CRUD (Создание, Чтение, Редактирование, Удаление). Использован ручной разбор request.POST без forms.py.

Запуск:
bash

cd Z2_1
python manage.py makemigrations
python manage.py migrate
python manage.py runserver

Главная страница: http://127.0.0.1:8000/
📝 Приложение Z2.2: Папка Z2_2 (Связь 1 ко многим)

Тема: Маршруты и рейсы.

    База данных: SQLite.

    Модели: Route (Маршрут) и Trip (Рейс). Один маршрут может иметь множество рейсов (ForeignKey).

    Реализовано: CRUD для обеих таблиц. При создании рейса используется выпадающий список (select) для выбора маршрута.

Запуск:
bash

cd Z2_2
python manage.py makemigrations
python manage.py migrate
python manage.py runserver

Главная страница: http://127.0.0.1:8000/
📝 Приложение Z2.3: Папка Z2_3 (Связь многие ко многим)

Тема: Продажа билетов.

    База данных: SQLite.

    Модели: Passenger (Пассажир), Trip (Рейс) и промежуточная Ticket (Билет).

    Реализовано: Связь ManyToManyField через промежуточную таблицу. CRUD для всех трех сущностей. Можно продать билеты одному пассажиру на разные рейсы, и на один рейс — разным пассажирам.

Запуск:
bash

cd Z2_3
python manage.py makemigrations
python manage.py migrate
python manage.py runserver

Главная страница: http://127.0.0.1:8000/
📝 Приложение Z2.4: Папка Z2_4 (Связь 1 к 1 + PostgreSQL)

Тема: Автобусы и их технические паспорта.

    База данных: PostgreSQL (драйвер psycopg).

    Модели: Bus (Автобус) и BusPassport (Техпаспорт). Связь OneToOneField.

    Реализовано: CRUD для автобусов и паспортов. В выпадающем списке при выдаче паспорта показываются только те автобусы, у которых еще нет паспорта.

⚠️ Настройка перед запуском:

    Убедитесь, что сервер PostgreSQL запущен.

    В DBeaver (или через консоль) создайте базу данных bus_db.

    В файле Z2_4/Z2_4/settings.py укажите ваш пароль от PostgreSQL в блоке DATABASES.

Запуск:
bash

cd Z2_4
python manage.py makemigrations
python manage.py migrate
python manage.py runserver

Главная страница: http://127.0.0.1:8000/

📝 Приложение Z3: Билетная касса

Назначение: заказ билетов на междугородние автобусы.

Структура модели:

    Passenger (Пассажир) — справочник пассажиров.
    Bus (Автобус/транспорт) — справочник автобусов.
    BusPassport (Техпаспорт) — связан с автобусом связью OneToOneField (1 к 1).
    Trip (Рейс) — связан с автобусом связью ForeignKey (многие к одному).
    Ticket (Билет) — главная (промежуточная) таблица. Имеет две связи многие к одному:
    на Passenger и на Trip.

Схема связей:

    Bus 1 ─── 1 BusPassport
      │ 1
      │
      ▼ M
    Trip M ◄─── 1 Ticket M ─── 1 Passenger

Реализовано:

    Полный CRUD для всех пяти таблиц (списки, создание, редактирование, удаление с подтверждением).
    Оплата и возврат билета: кнопки «Оплатить» и «Вернуть», дата оплаты/возврата и сумма возврата.
    Валидация при наборе данных: формат телефона, госномера и серийного номера техпаспорта,
    дата рождения и дата выдачи не в будущем, срок действия техпаспорта позже даты выдачи,
    цена больше нуля, города отправления и прибытия различаются, рейс не в прошлом,
    место в пределах вместимости автобуса, запрет двух билетов на одно место и на одного пассажира на один рейс.
    Связь 1 к 1: в выпадающем списке техпаспортов показываются только автобусы без техпаспорта.
    В формах POST используются выпадающие списки: пассажир, рейс, автобус, статус билета.
    Типы полей: CharField, EmailField, IntegerField/PositiveSmallIntegerField, DecimalField,
    DateField, TimeField, DateTimeField, BooleanField, ImageField (фото пассажира и фото автобуса),
    FileField (скан техпаспорта), ChoiceField (статус билета).
    Стоимость билета рассчитывается автоматически: цена рейса + багаж.
    Стили объявлены в теге <style> базового шаблона templates/base.html.
    Рисунки находятся в папке static/images: logo.svg, hero.svg, passenger.svg, route.svg.
    Используются базовый шаблон base.html, общий шаблон формы form.html и шаблон подтверждения удаления.

Запуск:

bash

cd Z3
python manage.py migrate
python manage.py seed_demo   # необязательно: демонстрационные данные
python manage.py runserver

Главная страница: http://127.0.0.1:8000/

Тесты:

bash

cd Z3
python manage.py test

💡 Примечания по архитектуре проектов Z2_1 – Z2_4

    Во всех CRUD-приложениях использован классический подход: данные извлекаются вручную через request.POST.get(), а шаблоны наследуются из общей папки templates в корне каждого проекта.

    Для удаления и редактирования используются функции с проверкой try/except на наличие записи в базе (DoesNotExist).

    В шаблонах реализован простой вывод таблиц (использован атрибут cellspacing и встроенные стили).
